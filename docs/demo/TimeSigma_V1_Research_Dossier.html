1.1

TimeSigma 项目概览

Project Overview

TimeSigma 并非单一的异常检测模型，而是一个面向时间序列异常检测研究任务的 LLM-first Research Agent。它以 Pi 作为 Agent runtime，以 EasyTSAD 作为标准化 benchmark，通过 Research Memory、Pipeline Planning、Formal Execution 和 Evidence Accumulation，支持从历史经验检索到实验执行与结果沉淀的完整科研闭环。

当前 TimeSigma 聚焦单变量时间序列异常检测（TSAD）。其目标不是直接提出一个固定的新 detector，而是在受控实验协议下，使 Agent 能够利用已有方法、历史 Evidence 与可执行 Pipeline 空间，自主提出、执行、诊断并积累研究方案。

2.1 Profile

Profile 是 TimeSigma 对时间序列任务的统计描述，为 LLM 提供可观测的数据特征，用于研究判断与历史比较。它不直接决定 detector 或 Pipeline。

Task 定义研究问题的身份与上下文，包括数据集、Schema、PlanningUnit 和目标指标；Profile 描述其中的数据特征，两者不是同一个对象。

Current Task Profile

来自当前任务允许使用的训练侧数据，向 Agent 描述研究对象。

  2. Current Profile

Historical Task Profiles

历史任务的比较背景

来自与历史任务和 Evidence 关联的 Profile，支持检索、比较与经验解释。

  1. LLM 查询
  2. Research Memory
  3. Profiles + Evidence

Profile 描述一个任务；Research Memory 组织历史任务、关联 Profile 和实验 Evidence。历史 Profile 通过数据来源与版本绑定读取，不是 Evidence 的独立顶层字段，也不包含 Research Memory。

当前 CurveProfile 共 18 个字段。频率以 cycles/sample 表示；部分统计在数学上未定义时为 null。历史 memory_read 的 source_profile 返回可用数值向量，Profile 来源缺失时可能为空。

Profile 只是研究上下文的一部分

Agent 还可读取 task / Schema、当前 Pipeline 与研究状态、历史 Evidence、历史 Profile 和 Capability。迭代研究包含 baseline、incumbent 与待执行 candidate；正式 one-shot 初始规划没有基于目标成绩选择的 baseline。

非 AIOPS 开发仍以当前 task 已评价合法默认 Component 中的最佳项作为固定起点；后续分支由 LLM 选择。这个起点政策不等同于 Memory 推荐。

2.2 Pipeline

Pipeline 是完整、可执行的异常检测配置，也是 TimeSigma 进行判断并最终绑定到实验的对象。

按编号与箭头顺序执行：原生 train / validation 划分 → differencing → native scaling → 可选 robust scaling → 可选 moving average → detector 分支 → 可选融合 → anomaly score。

Preprocessing｜输入处理

能力当前行为
raw / none原生缩放保持输入值；差分和其他可选步骤分别配置。
min-max按原生数据加载流程缩放数值范围。
z-score按原生流程以均值和标准差标准化。
robust scaling使用训练数据的中位数和 IQR 缩放；退化情况按现有规则处理。
differencing按 diff_order 计算差分，0 表示不差分。
moving average分区内的中心滑动平均，边缘采用固定填充；不会跨 train / validation / test 边界。

Detectors｜已注册的六个算法族

方法能否执行仍受原生 Schema 与参数约束；LOF / OCSVM 当前仅支持 naive，不能静默转换为共享训练方法。上游目录中存在其他代码，不表示已进入 Registry。

Limited Ensemble｜受限的双分支融合

最多两个兼容 detector 分支共享预处理，并要求相同原生 score 支持范围。每条曲线的两个分支分别做 average-rank normalization，再进行 equal-mean fusion。

当前不学习融合权重，不支持三分支以上组合，也不在看到结果后回退到最强分支。Pipeline 内部的 Ensemble 分支不是 Research Tree 的独立科学父节点。

Harness｜确定性科学保障

保障实际作用
Legality核对所提 Pipeline 的方法、Schema、参数与组合是否合法。
Semantic diff比较 resolved baseline 与 candidate，识别实际改变的科研维度。
Methodological Correction｜从动作标签到实际语义

“change algorithm → AE”曾将 AR(p=16, diff=1) 重置为 AE defaults(p=128, diff=0)，同时改变 detector、context/window 和 differencing。

一个新 ResearchStep 由一个实际语义研究维度的变化定义，而不是由一个 action 标签定义。

先解析 baseline / candidate，再计算 actual semantic diff，恰好一个允许维度变化才可执行。detector 替换在合法时保留共享维度，目标私有参数按声明默认值初始化；不兼容则拒绝，不静默重置。这不是“只改变一个数值字段”。初始 one-shot 完整计划不是基线过渡，而是协议产物。

保障实际作用
No-op拒绝科学配置实际未改变的候选。
Duplicate识别相同任务与等价 Pipeline，按合同复用已有 Evidence，避免重复消耗实验预算。
Preview / freeze执行前展开展示真实配置；正式交付锁定并冻结首个合法初始方案。
Budget执行预声明的规划、Provider 与实验额度，不由 LLM 增加。
Isolation限制历史可见性，阻止标签与禁止的目标结果进入规划。
Execution binding使执行、score 和评价对应同一个冻结配置与产物。
Evidence commit将已完成的配置、官方结果及模型 diagnosis 提交为可追踪记录。

2.5 LLM-first Design

需要科学判断的选择留给 Model；科学有效性与可复现性由 Harness 提供确定性保障。

Model / Scientific Judgment

Interpret · Search · Compare · Hypothesize
Plan · Diagnose · Continue

根据证据形成判断，处理不确定性与竞争解释。

Harness / Deterministic Guarantees

Legality · Identity · Semantic control
Execution binding · Visibility · Reproducibility · Persistence

使判断转化为合法、可追踪且可复现的实验。

  1. Retrieval is model-directed检索由研究判断驱动

    LLM 决定是否搜索、搜索什么、是否读取详情，以及采纳或拒绝什么经验。相似度排序不等于 detector 推荐。

    当前研究兼容路径可提供少量 Component 自动摘要；这仍是上下文，不替模型选择下一步。ResearchStep 主要通过主动查询获取。

  2. Historical Evidence is evidence, not policy历史记录不构成当前行动命令

    Memory 记录以前发生过什么；历史 next_action 或一次成功，不要求当前任务照做。

  3. Capability is grounding, not recommendation能力目录说明可执行范围

    Capability 回答“什么能合法执行”，由 Model 判断“当前任务值得尝试什么”。

  4. Interpretation remains separate from observation解释与观测分别保留

    实际配置和测量结果是事实；历史 diagnosis 是当时解释；当前 hypothesis 是需要验证的新判断。

  5. Non-negotiable guarantees remain deterministic科学合同不只依赖模型遵从

    合法性、semantic diff、隔离、精确 Pipeline 身份、score/evaluation 绑定及 Evidence 持久化，都由确定性代码落实。

LLM-first ≠ LLM-only

TimeSigma 将 LLM 放入可执行、可追踪、可复现的科研系统中。LLM 负责科研判断，Harness 负责不可妥协的科学约束；Pi 提供通用 Agent runtime，EasyTSAD 提供标准化实验执行与评价。

4.1 Capability Expansion｜扩展算法与 Pipeline 能力空间

Current V1 fact 当前 Registry 只有六个 detector 家族与受限的组合空间。

Possible direction

More TSAD Algorithms

可讨论 FCVAE、LSTMAD 系列、TranAD、TimesNet、FITS 等候选，扩展 Agent 能够开展科学规划的 detector landscape。

这些名称已在固定 EasyTSAD 源码与冻结榜单生态中核对，尚未进入 TimeSigma Registry。目标是丰富可研究对象，不是一次性接入全部榜单方法。

Possible direction

More Pipeline Components

可探索更丰富的特征变换、自适应预处理、残差建模、多阶段检测、更灵活的 detector 组合 / Ensemble，以及有科学依据的 score calibration。

这里保留研究动机，不定义具体组件或未来 DAG。复杂组合是否必要，应由独立验证决定。

新方法仍须明确 Method lifecycle、原生 Schema、可复现配置、适用的 Artifact / checkpoint、冻结执行、官方评价和 Evidence 生成；接入不能以削弱 Harness 为代价。

若扩展后性能提升，有多少来自更大的能力空间，有多少来自 Agent 的研究与规划能力？

4.2 Optimization Objectives｜单目标还是多目标优化？

Current V1 fact 同一 Pipeline 在点、事件、长度与延迟口径，以及对应 F1 / AUPRC 上可能有不同表现。当前协议每次运行预声明一个主指标，同一组 scores 产生八项官方指标。

Option A

Explicit Single Objective

One TimeSigma Core,
multiple Objective / Protocol configurations.

分别冻结 Point-F1、Event-F1、AUPRC 或 delay-sensitive 目标，复用同一个核心体系。目标清晰，更容易解释和比较；但优化一项指标可能牺牲另一项。

Option B

Multi-Objective Planning

让 Agent 显式处理目标冲突。例如 Point-F1 上升时 Event-F1 可能下降，AUPRC 改善也不保证更早发现异常。

候选方式包括主目标加次级约束、偏好权重、Pareto dominance / frontier，或按任务预先选择目标。“优化所有指标”还不是充分定义的科学目标。

Pareto 前沿关注这样的候选：无法在不牺牲其他目标的前提下，进一步改善某个目标。目标、偏好与选择规则仍需预先声明；不同目标配置是独立运行配置，不能事后拼接各 Pipeline 最好的指标列。

每次运行冻结一个明确目标，还是研究 Pareto 空间中的多目标规划？

4.4 Agentic RL｜学习怎样进行科研决策

Current V1 fact 当前主要依靠 LLM 对 task / Profile、Memory、工具结果及 Prompt / policy 约束进行推断。未来可研究交互轨迹和反馈能否改善研究策略本身，而不是直接训练异常 detector。

Possible learning targets

检索哪些 Evidence、下一项实验、何时回退或利用已有知识、何时停止，以及如何分配固定额度内的实验机会。

Reward signals to discuss

目标性能、信息增量、实验成本、非法方案、研究效率和有效停止；这里不预设最终奖励函数，也不允许策略增加 Runner 的预算。

主要风险包括 reward hacking、榜单过拟合、长程信用分配、昂贵交互，以及知识获取与性能优化的冲突。学习候选须在隔离的非 AIOPS 任务上验证，正式 AIOPS 反馈不作学习信号。

是否已有足够高质量轨迹支持 Agentic RL，还是应先加强轨迹质量与因果评价？

4.5 RSI & Self-Improving Agents｜从策略优化到受限自我改进

Current V1 fact V1 不执行 RSI：它没有自主改写核心 Harness，也不持续更新 Agent 的 LLM 权重。

积累 Evidence、提炼 Skills、优化研究策略、修改研究程序，以及改进“改进程序本身”，属于不同层次的问题，并非必须依次实现的路线。

Bounded Self-Improvement

限定可变的研究程序或策略，由外部标准决定改动是否值得保留。

Stronger Recursive Improvement

改进过程本身也成为改进对象，持续有效性、控制边界与评价独立性都需要更强证据。

Candidate design Agent 开展研究并积累轨迹，提出程序或策略改动；外部 benchmark 在独立任务上验证，接受后以版本发布，再影响后续行为。验证失败的改动可以拒绝或回退。

边界包括不可变 benchmark 合同、外部 evaluator、可复现 Evidence、版本与 rollback、held-out tasks，以及不允许静默自我修改。该循环尚未实现。

哪些研究程序可以允许自我改进，哪些科学保障必须始终由外部固定？
